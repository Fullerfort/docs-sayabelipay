---
title: Refund a Payment
description: "POST /api/refund"
---

Refunds a successfully paid transaction back to the customer's original payment method.

## Request

```
POST https://sayabelipay.com/api/refund
Content-Type: application/x-www-form-urlencoded
Authorization: Basic base64(client_id:client_secret)
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `transaction_id` | string | Yes | The transaction's reference (same value used for [transaction details](/api-reference/transaction-details)). |
| `refund_reason` | string | Yes | |
| `bank_code` | string | Yes | |
| `bank_account_number` | string | Yes | Numeric. |
| `account_name` | string | Yes | |
| `email` | string | Yes | |
| `amount` | string | No | Partial refund amount (decimal, e.g. `"5.00"`). Omit for a full refund. Must be less than the transaction's total. |

<Note>
  `bank_code`/`bank_account_number`/`account_name`/`email` are required by this endpoint's validation on every account, but the refund itself goes back to the customer's **original payment method** automatically — these fields aren't used to redirect the money to a different destination. Send real, non-empty values to pass validation regardless.
</Note>

<CodeGroup>

```bash cURL
curl -X POST https://sayabelipay.com/api/refund \
  -u "YOUR_CLIENT_ID:YOUR_CLIENT_SECRET" \
  -d transaction_id=9B8FEEB60F9E3 \
  -d refund_reason="Customer requested" \
  -d bank_code=MYBB \
  -d bank_account_number=1234567890 \
  -d account_name="Jane Tan" \
  -d email=jane@example.com
```

```php PHP
$response = Http::withBasicAuth($clientId, $clientSecret)->asForm()->post(
    'https://sayabelipay.com/api/refund',
    [
        'transaction_id' => '9B8FEEB60F9E3',
        'refund_reason' => 'Customer requested',
        'bank_code' => 'MYBB',
        'bank_account_number' => '1234567890',
        'account_name' => 'Jane Tan',
        'email' => 'jane@example.com',
    ]
);
```

</CodeGroup>

## Response

```json
{
  "status": 200,
  "data": {
    "status": "success",
    "...": "full refund object from the processor"
  }
}
```

### Not eligible

Only a transaction that reached a successful/paid status can be refunded. Refunding one that's still `Pending`, already `Refund`ed, or in a failed state returns:

```json
{ "error": 400, "message": "Only successfully paid purchases can be refunded." }
```

### Not found

```json
{ "error": 404, "message": "Transaction not found" }
```

Returned both when `transaction_id` genuinely doesn't exist, and when it belongs to a different merchant account — this endpoint never confirms or denies the existence of another merchant's transactions.
